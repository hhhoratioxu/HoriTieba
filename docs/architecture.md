# 架构与一致性边界

## 0.4.0 两个页面入口

贴吧列表与主题分别挂载「自动评论」和「自动回复」。内容脚本只接受可信点击和同一扩展的消息，普通导航和同文档导航都会按当前页面更新入口。每一项都绑定开启它的标签页及论坛名或主题编号。

列表运行复用新帖扫描、发布时间核实、跨批次去重和一级评论编辑器。每批只有一个循环取用的一级评论文本，不改写旧的用户配置和库。开始前的列表是基线。待核实的新帖也从已保存的队列继续检查，关闭或离开列表会停止调度。帖子里的逐条回复继续使用原评论编号。同一账号的两种任务通过数据库事务共用发送间隔，未使用的准备预留会被取消或到期释放。

## 单篇帖子入口

0.3.0 将输入栏放进帖子底部的隔离 Shadow DOM。点击「开始」会把当前帖子、标签页、已核对的账号和回复原文绑定到一个批次。内容脚本通过贴吧原有的楼层、楼中楼回复和分页控件工作。针对某条楼中楼，先在该条独立编号对应的节点点击「回复」，再保留原生收件人标签追加原文。后台在一个 IndexedDB 事务里占用该账号、帖子、原评论编号的唯一记录并检查发送间隔。成功证据包含新增评论编号、父楼层、实际账号、原文及楼中楼收件人。帖子只回显收件人时，原目标编号依据点击时绑定的原评论节点保留。

关闭标签页、离开本帖或重新启动浏览器都会结束监控。一次可能已经提交的回复只做只读核实，保留去重标记。高级控制台的真实自动任务与本帖任务互斥。

## 高级控制台

```text
dashboard / sidepanel / popup (React)
        │ 严格类型消息 + requestId + 来源验证
        ▼
message-router / Service ── 分页读取模型
        │
Engine ── 单队列 + 执行租约 + 配置版本 + 停止 epoch
        ├── alarms 调度 / 恢复检查
        ├── Repository / IndexedDB 原子事务
        └── PlatformAdapter
             ├── DemoAdapter → 独立本地演示账本
             └── TiebaAdapter → WorkTabs → 隔离内容脚本 / PageDriver → 正常 DOM 交互
```

React 只编辑配置和显示后台快照，不承担队列或发送逻辑。所有视图共享同一后台和数据库。每次 alarm 最多检查一次、发送一个阶段；一帖的启用步骤完成或暂停前，不越过它发送后续帖子。真实自动发送要求冻结配置的 `realAction=auto`，并在启动预检与摘要确认间保持账号 ID 一致。旧配置缺少该字段时按只读处理。

现代版页面保留只读支持。自动模式通过普通页面中的官方旧版入口进入经验证的结构，由 legacy.ts 负责列表、主题、账号、父子评论和时间证据。列表不假造创建时间；每轮最多 2 个新增候选读取主题一楼，待核实记录可后续补证，基线记录永不转为补发任务。

旧版账号默认核对顶部两个主页标识与侧栏头像、主页。Chrome 实机另观察到主题页顶部 `#j_u_username` 长期为空、侧栏完整的结构；仅此结构且不存在顶部身份链接、我的贴吧入口或登录文字时，可用 `#user_info` 的头像标识、头像主页与唯一昵称主页三处相等的 ID 确认。它仍必须与启动时列表页绑定的账号一致；任何冲突、重复或缺失都阻断，不依靠帖子作者昵称推断登录人。

## 存储模型

IndexedDB 版本 1，包含 meta、configs、libraries、cursors、runs、threads、tasks、attempts、dedupe、leases、logs、demoLedger。账号绑定和配置快照在 Run/Task 内，独立步骤嵌入 Task，以保证同一事务提交。索引覆盖 mode、runId、taskId、status、firstSeen、日志时间；Task 的账号＋帖子 dedupeKey 为唯一索引，并另存不可被历史清理绕过的 dedupe 标记。

所有模式的键包含 demo/real，实例和内容游标隔离。运行冻结配置与库版本；版本的条目数组不随控制台更新。当前库的新版本使用新游标键，旧运行继续提交旧版本游标。

数据库使用严格持久化事务。升级通过 openDB 的 schema upgrade 入口完成；当前没有旧生产版本，不能宣称已验证历史版本迁移。versionchange 会关闭旧连接；升级被占用则明确提示，不删除数据库。

## 发送顺序

1. 在事务中将选中的条目、文本、库版本、游标、开始时间冻结到步骤。
2. 适配器准备目标。校验当前账号、帖子、自己的首评 ID、作者和编辑器语义。
3. 先写 SendAttempt intent，包含 beforeIds 与目标。然后再检查运行状态、epoch、额度。
4. 在外部提交前写入 submitted 标记并占用额度。标记与实际外部动作之间若发生崩溃，也视为未知。
5. 内容脚本持有一次性准备 token，输入后向后台请求点击许可。后台在事务中再次检查工作页、顶层 frame、尝试、运行 epoch、额度和步骤，持久化单次 clicked 记录。页面再核对账号、原文、评论集合与编辑器位置后，普通 DOM 点击一次；丢失 token 不补发。
6. 读取结果证据。需发送前不存在的新评论 ID、正确作者、帖子、根楼层、回复目标、完整文本及时间范围都匹配且只有一个候选。一级评论用 post_id，楼中楼用 pid/spid；不执行 data-field 字符串。日期使用 UTC+8 分钟区间，不能把页面分钟时间当成精确秒。
7. 新楼中楼的临时节点可能没有 spid，不算成功。有限轮询中最多一次无草稿刷新，重新展开自己的首评，寻找正式节点；仍不确定则未知，不重复点击。每次追评准备也先无草稿刷新，绑定服务端保留的首评结构。
8. 一个本地事务中提交 attempt、step、游标、成功统计和首评关联（包括所在分页 URL）。重复核实不会重复推进。

本地事务不能与平台发布组成同一事务。提交超时、后台中断或证据不足都转为未知。未知占用额度，阻断后续步骤；用户核实或明确决定承担重复风险后才能重试。人工确认的证据来源与 DOM/演示证据不同。

## 互斥、取消与恢复

每种模式有 120 秒持久化执行租约，配合唯一任务键和运行 epoch。列表加载最多 6 轮，主题加载在 20 秒总窗口内重试（最多 40 轮）。普通页面消息限时 8 秒。编辑器准备使用 15 秒绝对截止时间，通信另留 3 秒回传结果。只读展开的页面预算为 10 秒，发送状态诊断限时 2 秒。单次扫描上限 100 条，详情核实上限 2 个。解析器读取最多 100 个根楼层、每楼最多 200 个已加载楼中楼；分页或数量不完整时不允许按不完整快照追评。程序不把过期租约等同于“之前没发出去”，先看持久化未完成步骤和发送日志。

0.2.1 将后台与内容脚本的异步回应统一为浏览器兼容方式：Safari 返回 Promise，Chrome 使用回调与 `return true`。页面 `pagehide` 后取消准备并停止响应业务消息，`pageshow` 恢复；导航和刷新仍必须等到新的文档标识。发送许可等待限时 5 秒，同时检查绝对截止时间，防止主线程挂起后迟到的许可触发点击；超时会恢复原草稿，不重发。

提交响应丢失后，先取消页面准备状态、将尝试置为未知并暂停批次，再进行一次有界的只读核实。若找到唯一的正式评论证据，只提交一次成功和游标，批次仍保持暂停；没有证据则继续保持未知。只读发送阶段诊断用于区分等待许可、点击前和点击后，不将许可或点击记录当作平台发布成功。

工作标签页仅复用扩展保存的 ID，不接管用户原页。检查到草稿后禁止刷新/导航。标签页关闭会清理失效 ID 并报告未知或阻断；之后显式重新核实可创建工作页。页面被导航到别的主题时不会依据错误上下文核实成功。

Chrome 实机详情页曾在约 11.1 秒才完成 DOM 加载，因此导航等待使用 20 秒总窗口；短暂没有消息接收者时仅等候，不反复刷新或点击版本切换。旧版楼中楼的 `hideLzl` 空容器即使有布局矩形也属于收起状态；必须先按该楼的正常回复入口展开，再验证 `pid`、已加载数量与自己的首评一致，之后才显示编辑器。

超过页面等待窗口的临时加载失败，在尚未创建发送尝试的准备阶段可分别延后 30、60 秒自动重试，次数保存在步骤内。两次仍未就绪则阻断；账号冲突、草稿、验证码等不走这条路径。取消或暂停的 epoch 优先，已有发送尝试绝不进入准备重试；提交后超时仍按未知停止，不能借此补发。

暂停/停止消息可以在准备阶段更新 epoch，发送许可事务会拒绝旧 epoch。已标记提交的动作继续核实，不标成“已撤回”。后台干净恢复保留原定时间，不反复延后计划；逾期时最多执行一轮，并按当前时刻计算下次间隔。系统时钟明显回退会阻断。浏览器完全关闭不能执行。

Chrome 官方说明扩展 worker 可能被终止，应持久化状态：[生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。本项目不假设后台常驻。调度使用 [alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms)，每次启动恢复/重建；最低节奏设为 30 秒，但不承诺精确时刻。Edge 侧边栏 API 的设计参考 [Microsoft 官方文档](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/sidebar)，尚未完成品牌 Edge 原生测试。

0.2.2 在页面节点上短暂监听楼层、父编号、编辑器及按钮的变化。超时或取消会移除监听。准备请求绑定文档标识、操作编号和截止时间，迟到的回执不能发放新票据。队列只在创建发送尝试之前恢复准备，在持久化日志中留下原因。隐藏页重试时会显示登记的执行页并重新检查。只读展开也可以在原楼层再核验一次。Chrome 会限制隐藏页的定时器和视觉更新，设计依据见 [Chrome 后台计时器说明](https://developer.chrome.com/blog/timer-throttling-in-chrome-88/)。

## 性能与边界

界面按变更消息读取当前视图，列表每页 25 条；非内容库页不传 25000 条内容。当前选中内容库用于编辑时最多读取 5000 条，但渲染仍分页。帖子增量写入；阅读旧位置时暂存新结果提示。日志限制 2000 条。TXT 每 500 行让出主线程并报告进度。

读取模型目前会在后台按模式读取并过滤最多 10000 条帖子；它不是无限规模索引搜索。性能报告只反映已测数据量，不承诺任意增长都流畅，也没有长期内存泄漏结论。持续运行需主动导出/清理历史。普通页面不被注入长期 observer，内容脚本仅保留一个消息监听器。
