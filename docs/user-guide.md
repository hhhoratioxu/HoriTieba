# 使用说明

## 本帖自动回复

1. 在已登录贴吧的 Chrome 中打开一篇具体的帖子。
2. 在页面底部「本帖自动回复」输入要回复的文字，点击「开始」。
3. 保留帖子标签页。想结束时点「停止」或关闭它。

扩展会自动翻过帖子和楼中楼的分页，逐条回复其他人的评论，跳过主题正文和自己的评论。扫完后会等待新评论。发送至少间隔 30 秒。同一账号在同一帖子里，每条原评论只处理一次；刷新或重新启动仍保留记录。新版贴吧会通过网站提供的入口切换到旧版视图。

遇到验证码、草稿或无法核实的发送会暂停。结果不明时可点「核实」只读检查；「跳过此条」会保留去重记录。此功能独立于下面的控制台模式，不需要配置内容库。

## 完成一次本地演示

1. 打开控制台，保留“演示模式”。顶部和内容区始终显示模式标识。
2. 在“内容库”管理首评、回复 1～4。默认仅启用回复 1 与回复 3，因而执行顺序为首评 → 回复 1 → 回复 3。未启用的步骤显示“未启用”。
3. 在“设置”中选择总开关、标题规则和额度。点“保存设置”。
4. 点“开始”，检查启动摘要后确认。摘要版本过期会被后台拒绝，需重新查看。
5. 首次检查只建立历史基线；下一个允许检查时刻生成明确标注的演示新主题。发送和核实都发生在本地演示账本。
6. 在任务详情查看每步文本快照、库版本、游标、账号、首评关联、时间、尝试 ID 和证据来源。关闭控制台后 alarm 仍可继续调度，重新打开可恢复查看。

总览的成功数仅在核实后增加。点击发送、创建意图和编辑器清空都不会直接计为成功。演示成功不代表已向贴吧发布。

## 五个内容库

- 编辑支持多段文本和表情，单条最多 2000 字符、每库最多 5000 条；这是本地产品约束，不是平台官方长度限制。
- TXT 按行导入，识别 UTF-8、BOM、CRLF/LF、空白、首尾空格。展示总行数、有效、空行、重复和超长数量；默认追加与保留重复，可显式选择去重。替换需确认。
- 排序使用每条的上移/下移按钮。搜索只改变显示，不改变排序。
- 点击“保存内容库”才持久化。保存会建立新版本，新版本游标从 0 开始，下一次运行使用。当前运行继续使用冻结版本。
- 循环关闭时，用尽会暂停；循环开启时取回首条，但额度不会重置。
- TXT 导出按行拼接，多段条目可能丢失边界；保留内部换行和所有配置请用“全部导出”的 JSON 包。
- JSON 包只接受 schemaVersion 1、五个不同库和白名单配置字段。导入预览后明确确认替换。旧版本、异常类型、重复条目 ID、未知配置字段会拒绝。
- 重置游标必须停止运行且没有未知结果。清空和替换会要求用户确认。

## 最新帖子

标题包含规则支持任意或全部包含；关键词不区分大小写，排除关键词任意命中即排除。作者按完整昵称或已识别 ID 精确排除。

初始基线只展示；后续还须有可靠创建时间晚于启动时间。旧帖上浮、置顶、推荐、广告、不可靠来源和已处理帖子不能自动入队。真实自动模式逐个读取主题一楼的完整时间（UTC+8，分钟精度）；与启动分钟重叠的帖子保守跳过，未来时间也不能入队。列表上的“创建时间”可能缺年份，“最后回复时间”只表示活跃程度，均不直接拿来建任务。

每次检查最多核实 2 个新增主题；暂未核实的新增条目保留到后续扫描。当前列表最多读取 100 条，不能保证覆盖未加载的帖子；基线旧帖不会因稍后取得时间而补发。

列表每页 25 条，搜索和筛选由后台读取模型处理。用户阅读旧位置时，新帖显示提示，不强制滚动。已经执行或手动跳过的账号＋帖子去重标记会跨运行保留，清理历史也不会移除。

## 暂停、停止与恢复

| 操作           | 实际含义                                                             |
| -------------- | -------------------------------------------------------------------- |
| 暂停           | 禁止启动新发送，已提交操作继续核实，队列保留                         |
| 继续           | 只从安全步骤继续，未核实或明确失败步骤需先处理，发送间隔继续生效     |
| 停止           | 结束当前批次，未执行部分停止，保留历史                               |
| 紧急停止       | 立即请求禁止新发送并取消可取消的准备；不声称已经提交的内容被撤回     |
| 重新读取核实   | 只读取已有发送证据，不再次点击发送                                   |
| 手动标记已发布 | 输入真实评论标识和依据后提交一次游标，证据明确标记“用户手动确认”     |
| 明确重新尝试   | 提示重复发布风险并确认，旧尝试保留、旧额度不退还，需继续运行后才尝试 |

演示模式可模拟成功、明确拒绝、验证码、发送后连接中断、账号变化、追评目标不符与工作标签页关闭。结果未知场景在账本中保存了模拟评论，可通过“重新读取核实”恢复，不能自动重发。

正常后台回收恢复原计划，逾期计划最多执行一轮。发现持久化 intent/submitted 状态则进入未知并暂停。存储失败会禁止当前后台继续发送；恢复后再次检查未完成记录。工作标签页关闭或出现草稿时只读检查会显示失败原因并退避，不会覆盖输入。

## 真实自动运行

1. 在安装扩展的同一浏览器资料中正常登录贴吧。进入控制台切换“真实模式”，输入贴吧名称或 HTTPS 贴吧列表链接；也可从贴吧页的扩展弹窗“识别当前贴吧”。
2. 在设置中选择“只读观察”或“自动首评与追评”。只读不会创建发送任务；自动模式会使用网站官方旧版入口，并复用最多两个工作标签页。
3. 导入首评库和需要启用的回复库，设置“回复自己”总开关、各阶段开关、筛选及运行额度，分别保存。首评是自己的一级评论，后续各阶段都回复该首评；不支持改为回复上一条追评。
4. 点击“开始”。自动模式先读取当前实际账号，摘要会展示账号 ID、贴吧、内容预览、启用阶段和数量。身份未确认、摘要过期或账号改变时不能启动。
5. 确认摘要后自动执行。首次扫描只建历史基线，之后经创建时间核实的新主题才会入队。每次调度最多发送一个阶段，首评核实成功后才会执行追评，不需要逐条确认。
6. 在任务详情核对首评 ID、楼中楼 ID、父评论关系和证据。已提交内容缺少独立编号时保持待核实；系统可在工作页没有草稿时刷新一次读取正式结果，仍无唯一证据则暂停为“结果未知”。

旧版账号依据顶部个人中心、“我的贴吧”和侧栏头像/主页中的多个稳定 ID 交叉核对；缺失或冲突时不以昵称替代。发送前再次检查账号、主题、自己的首评和编辑器上下文。回复对象无法确认时停止，不改发成新楼层。

工作页被关闭后，本次未明确的发送进入未知；“重新读取核实”可重新打开原主题进行只读恢复。草稿会阻止刷新和继续发送，请人工处理草稿。不要把原文仍在编辑器或评论区出现相似文本直接视为成功，也不要对未知结果反复重试。

品牌 Chrome 156.0.8078.80 已实机完成一个新帖的自动首评、四次回复自己的首评及到量结束。0.2.2 在工作页慢加载时会自动重新准备，最多两次。需要时会显示自己的执行标签页。已经提交的评论进入只读核实。Edge 和多日运行未验收。具体证据见 [Chrome 验收](chrome.md) 和 [真实接入验证](verification.md)。
