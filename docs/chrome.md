# Chrome 实机记录

## 列表停在 0 的实机诊断

旧版本的后台记录显示已建立基线，但工作页关闭和详情页缺少旧版入口都会使整轮检查延期。连续读取失败时，工作页实际停在贴吧的删帖页。另开只读标签核对了同一列表中确有创建于启动后的有效主题。诊断过程没有触发发表。[0.4.1 回归范围](verification.md)

## 0.4.0 贴吧列表与帖子

在 macOS 品牌 Chrome 的扩展管理页将已安装版本原位重载为 0.4.0。在真实贴吧列表看到「自动评论」及「给本吧每篇新帖发一条评论」输入框；在真实主题页看到「自动回复」及「回复本帖的评论和楼中楼」输入框。分别用原生工具栏图标定位输入框并试填。两页均能从空输入的「开始」禁用状态切换为可用，清空后恢复禁用。全程未启动真实发言，两页真实发布合计 0 条。

自动发送使用隔离浏览器另外验证。列表测试中，四篇新帖各收到一条一级评论，旧帖顶起及重复扫描均未触发发表；滑出可见列表的已观察候选得到后续核实。帖子测试验证同一人两条不同楼中楼的目标、两种分页、去重、停止和结果未知保护。[列表测试](evidence/forum-e2e.json) · [帖子测试](evidence/thread-reply-e2e.json)

## 帖子底部入口 · 0.3.0

在 macOS 的 Google Chrome 156.0.8078.80 中原位重载扩展，随后刷新真实贴吧帖子。页面底部出现「本帖自动回复」。输入文字后「开始」可用，清空后按钮恢复禁用。此次验收保持待机，真实发布 0 条。

同一构建在隔离 Chromium 中验证了一级评论和楼中楼回复、同一作者的两条原评论、两种分页、等待新评论、停止后重启去重、关闭帖子和未知结果保护。[自动回复隔离测试](evidence/thread-reply-e2e.json)
